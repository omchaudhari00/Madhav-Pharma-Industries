# Editorial Architecture Portfolio

Build a studio portfolio that earns attention through composition, photography,
and information hierarchy rather than visual effects. It should feel like a
well-edited architecture monograph translated into a fast digital experience.

## Originality boundary

Never reuse the source studio's projects, renders, project names, descriptions,
statistics, awards, partner marks, contacts, office addresses, or visual grids
as a close duplicate. Work from the new studio's own portfolio and verified
credentials.

## Visual direction

- Use near-white, warm-white, or pale stone backgrounds with black or deep-gray
  type. Let the project images provide the color.
- Pair a small utilitarian sans for navigation, labels, and metadata with a
  reserved serif for selected statements or architectural philosophy.
- Keep a fixed, extremely light header: stacked studio mark at left, text-only
  navigation at right. Avoid large buttons.
- Give photographs large uninterrupted fields. Use captions as quiet metadata:
  project, location/type, area, year, and a simple “View” action.
- Use whitespace as pacing. Dense facts belong in narrow bands, not card-heavy
  dashboards.

## Page architecture

1. **Hero image** — one full-frame original project shot with the studio name.
2. **Point of view** — a short statement about method, sustainability, craft,
   or context, followed by a compact facts list: founding year, lead, services,
   awards, publications.
3. **Capabilities** — explain the studio's work from concept through delivery.
   Use diagrams, materials, or sketches only when they belong to the studio.
4. **Selected projects** — an asymmetric editorial grid: feature one project at
   a generous scale, then vary subsequent project crops and sizes. Each links to
   a detailed, image-led case study.
5. **Method and people** — short process essays, team context, and meaningful
   studio statistics.
6. **Recognition and partners** — verified awards, publications, and client
   marks, presented as evidence rather than decoration.
7. **Contact/footer** — office/contact details, social links, and legal routes.

## Interaction and motion

- Use slow image fades, crop reveals, and modest parallax only when they improve
  the reading rhythm.
- Project cards should offer a clear hover/focus state without dramatic scale or
  zoom. The image must still feel stable and inspectable.
- Smooth scrolling is optional; if supplied, it must not prevent keyboard
  navigation, anchor links, normal browser find, or reduced-motion behavior.
- Do not use autoplay video or WebGL as a substitute for excellent photography.

## Build guidance

- Use a structured project model: title, slug, category, location, year, area,
  lead image, gallery, credits, and short description.
- Preserve accessible heading order and provide accurate image descriptions for
  non-decorative work. A project image cannot be the only way to understand it.
- Serve responsive images from a CDN, keep crops intentional, and prevent image
  reflow with width/height or aspect-ratio.
- Build project detail pages as first-class content, not modal galleries.

## Delivery checklist

- Typography, not animation, provides most of the sense of precision.
- Project imagery and credentials are authentic to the new studio.
- All project cards and detail pages work by keyboard and on narrow screens.
- The result feels like a distinct studio with its own point of view—not a clone
  of a reference portfolio.
